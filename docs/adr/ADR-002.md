# ADR-002: Separating System State from Service-Specific Artifacts

## Requirement
Services must not act as the persistence layer for global system state. While ADR-001 mandates that services manage their own internal execution artifacts, they must not directly manipulate the project-level `metadata.json` or global state dictionary.

## Decision
1. **Operational Ownership**: Services remain responsible for managing their internal operational artifacts (temporary files, process-specific inputs/outputs) as required by ADR-001.
2. **Access Restriction**: Services will NOT access or mutate global system metadata (the `Project` state dictionary) directly.
3. **Output Persistence**: Services are permitted to write their specific result artifacts to the filesystem (e.g., transcription text, clips) to maintain autonomy.
4. **State Delegation**: Any changes to global project status or system metadata must be handled by the orchestrator after the service returns its results.

## Justification
* **System Integrity**: This preserves the operational autonomy mandated by ADR-001 while maintaining a strict boundary that prevents business logic from becoming coupled to the global system metadata schema.
