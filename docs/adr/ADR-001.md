# ADR-001: Service Implementation Pattern

## Requirement
All services must follow a consistent implementation pattern to ensure state consistency and functional autonomy.

## Decision
1. **Service Definition**: A service is a self-contained component responsible for a single functional mandate (e.g., Video Manipulation).
2. **Operational Ownership**: Each service is responsible for its own operational environment. This includes managing required artifacts, filesystem interactions, and model/engine lifecycles.
3. **Mandatory Execution Protocol**: All services must implement the standard execution protocol:
   - `reset_metadata()`: State initialization and artifact cleanup.
   - `start_service()`: Lifecycle initialization and state transition.
   - `execute()`: Core domain processing.
   - `end_service()`: Finalization and state closure.

## Justification
* **Functional Autonomy**: Encapsulating operational responsibilities within the service allows it to fulfill its mandate as a black box without external dependencies.
* **Orchestration Decoupling**: The orchestrator is limited to flow control and does not need to know the internal operational requirements of any service.
