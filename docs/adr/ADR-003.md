# ADR-003: Standardized Testing Infrastructure

## Requirement
The test suite previously suffered from brittle "Integration-as-Unit" testing, manual/redundant mocking, and inconsistency in setup logic.

## Decision
1. **Isolation Standard**: Tests must not rely on actual File System, Network, or third-party APIs; use `unittest.mock` to stub these boundaries.
2. **SRP Focus**: Tests must exclusively verify service-level input-to-output logic.
3. **Dependency Injection**: Use manual dependency injection (passing mocks) rather than global patching.
4. **DRY Test Infrastructure**: All common infrastructure mocks (Credentials, Settings, FileSystem) must be defined as `pytest` fixtures in `backend/tests/unit/conftest.py`.
5. **Object Factories**: Use `factory` fixtures (e.g., `project_factory`, `uploader_factory`) for complex objects, ensuring a single source of truth for test data.
6. **Infrastructure Assumption**: Stop testing infrastructure instantiation errors (e.g., checking if `initialize()` fails); rely on type annotations and constructor injection.
7. **Coverage Policy**: Non-testable execution methods must be explicitly excluded from coverage metrics using the `# pragma: no cover` directive on the method signature.

## Justification
* **Test Maintainability**: Consolidating setup logic into fixtures creates a single source of truth, making tests easier to refactor when models change.
* **Execution Efficiency**: Isolating the service layer ensures tests are deterministic, fast, and decoupled from global persistence schemas.
* **Metric Accuracy**: Using `pragma: no cover` ensures that execution-only methods, which fall outside the scope of unit testing, do not unfairly penalize coverage metrics.
